The repo-root [`SECURITY.md`](../../SECURITY.md) is the GitHub-native entrypoint (vulnerability reporting, supported versions, disclosure window, scope). ## Conventions

- **Every threat is concrete.** If we cannot describe a believable attacker action, the row is omitted rather than padded.
- **Every mitigation cites code.** Mitigations link to the file (and ideally the function) that enforces them. If the mitigation is FUTURE work, it is labelled `FUTURE` and tagged with the intended phase.
- **Severity** uses a small ordinal scale: `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`. We do not compute CVSS yet — once we do, severity will become a CVSS v3.1 base score.
- **Sapphire posture** is a separate-but-adjacent concern. We reference [`~/Code/Sapphire/CLAUDE.md`](https://github.com/arigatoexpress/Sapphire/blob/main/CLAUDE.md) (the operator's canonical reference) for any claim about how Sapphire handles a shared concern (e.g. the `~/.sapphire/secrets.env` mode-0600 pattern).
- **Phase tags.** Mitigations are tagged with the phase that delivers them: `Phase 0` (Mavic + Mac + Pis, today), `Phase 0.5` (sensor-mesh add-on), `Phase 1` (Holybro X500 V2 + Cube Orange+ + Jetson Orin Nano Super, future).

## Maintenance

- Update the threat model on any of these triggers: a new code path that touches the signal pipeline; a new third-party integration; a new dependency that handles secrets; a change to schema versioning; a change to the BOM that adds a new attack surface.
- The **threat model file is dated** (`threat_model_2026-05-02.md`). When materially revised, copy the file to a new dated filename and update the `README.md` link. Old versions stay in tree as audit trail.
- The SBOM at [`../sbom/wildfire_watch_v0_0_1_sbom.cdx.json`](../sbom/wildfire_watch_v0_0_1_sbom.cdx.json) is regenerated by [`../sbom/generate_sbom.py`](../sbom/generate_sbom.py) on every dependency change.
